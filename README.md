# Админка рассылок Telegram

Веб-панель для ручных массовых рассылок сообщений подписчикам двух Telegram-ботов
(A и B). Позволяет создать кампанию, прогнать dry-run (проверку членства в чатах
без реальной отправки), отправить тестовое сообщение себе, запустить настоящую
рассылку с прогресс-баром в реальном времени и выгрузить результат в CSV.

## Стек

- Python 3.12
- FastAPI (веб-сервер и роуты)
- Jinja2 (шаблоны, серверный рендеринг)
- HTMX (динамическое обновление статуса без SPA/JS-фреймворков)
- SQLite (собственная база кампаний `data/broadcast.db`; базы ботов открываются
  только на чтение)

## Структура проекта

```
app/
  __init__.py
  config.py        # настройки из .env (НЕ трогать без согласования)
  db.py             # собственная БД сервиса: кампании, получатели, кэш членства (НЕ трогать)
  sources.py        # read-only доступ к базам ботов A и B
  auth.py           # логин, cookie-сессия, CSRF
  worker.py         # фоновая рассылка / dry-run
  telegram.py       # обёртка над Telegram Bot API
  main.py           # FastAPI-приложение и все HTTP-роуты (+ /health)
  templates/        # HTML-шаблоны (Jinja2), интерфейс на русском
  static/           # style.css, htmx.min.js, editor.js (панель форматирования)
tests/              # pytest
data/               # локальная база broadcast.db (в .gitignore)
requirements.txt
.env.example
Dockerfile
docker-compose.yml
README_broadcast.md  # инструкция по деплою на VPS
```

## Установка и запуск локально (Windows)

1. Создать виртуальное окружение (один раз):
   ```
   python -m venv .venv
   ```
2. Активировать его (каждый раз перед работой):
   ```
   source .venv/Scripts/activate
   ```
3. Установить зависимости:
   ```
   pip install -r requirements.txt
   ```
4. Скопировать `.env.example` в `.env` и заполнить (см. раздел ниже).
5. Запустить сервер:
   ```
   uvicorn app.main:app --host 127.0.0.1 --port 8080 --reload
   ```
6. Открыть http://127.0.0.1:8080 и войти по паролю из `ADMIN_PASSWORD`.

## Подключение сервисов и переменные окружения (.env)

Скопируйте `.env.example` в `.env` и заполните значения. Реальный `.env` **не**
коммитить и не выводить в чат/логи.

| Переменная | Назначение | Где взять / как сгенерировать |
|---|---|---|
| `TELEGRAM_BOT_TOKEN_A` | Токен бота A | У [@BotFather](https://core.telegram.org/bots#botfather) в Telegram: `/mybots` → выбрать бота → API Token |
| `TELEGRAM_BOT_TOKEN_B` | Токен бота B | Аналогично, у @BotFather для второго бота |
| `ADMIN_PASSWORD` | Пароль входа в админку | Придумать самостоятельно, хранить только в `.env` |
| `SECRET_KEY` | Секрет для подписи cookie-сессии и CSRF-токена | Сгенерировать: `openssl rand -hex 32` |
| `ADMIN_CHAT_ID` | Telegram chat_id администратора — куда уходит «тест себе» | Узнать свой ID у [@userinfobot](https://t.me/userinfobot) |
| `BOT_A_DB_PATH` | Путь к БД бота A (`bot_data.sqlite`, таблица `user_tg`) | Путь на диске/в контейнере, БД открывается только на чтение |
| `BOT_B_DB_PATH` | Путь к БД бота B (`chat_logs.db`, таблица `user_tg`; таблицу `user_vk` сервис не читает) | Путь на диске/в контейнере, только на чтение |
| `BOT_A_DATA_DIR` | Каталог **на хосте (VPS)** с базой бота A (только `bot_data.sqlite`, ничего лишнего) — монтируется целиком, read-only | Например `/opt/bginfobot/data` |
| `BOT_B_DATA_DIR` | Каталог **на хосте (VPS)** с базой бота B (`data/`, отдельно от исходников и `.env` бота B) — монтируется целиком, read-only; так подхватываются и файлы WAL-режима (`-wal`/`-shm`), если бот B их создаёт | Например `/opt/bginfoai/data` |
| `BROADCAST_DB_PATH` | Путь к собственной базе сервиса (кампании, снапшоты, кэш) | По умолчанию `data/broadcast.db` |
| `UPLOADS_DIR` | Каталог для загруженных картинок кампаний | По умолчанию `data/uploads` (внутри тома `./data`) |
| `EXCLUDE_CHATS` | Список чатов-исключений через запятую (участников не рассылаем) | По умолчанию `@bginfosuchat,@bginfosu` |
| `SEND_DELAY` | Пауза между отправками сообщений, сек | По умолчанию `0.08` (~12 сообщений/сек, лимит Telegram) |
| `MEMBER_CHECK_DELAY` | Пауза между вызовами `getChatMember`, сек | По умолчанию `0.1` |
| `MEMBERSHIP_TTL_HOURS` | Срок жизни кэша членства для статуса «участник», часов | По умолчанию `24` |
| `MEMBERSHIP_TTL_NONMEMBER_HOURS` | Срок жизни кэша для «не участник» (короче — риск пропустить нового участника) | По умолчанию `1` |
| `HOST` / `PORT` | Адрес и порт, на которых слушает сервис | По умолчанию `127.0.0.1:8080` — наружу не выставлять |
| `HOST_PORT` | Порт **на хосте** для docker-compose (внутри контейнера всегда 8080) | Сменить, если порт занят другим проектом на сервере, см. `README_broadcast.md` |
| `COOKIE_SECURE` | Secure-флаг сессионной cookie | `0` при доступе через SSH-туннель, `1` — если админка за HTTPS |
| `LOG_LEVEL` | Уровень логирования | По умолчанию `INFO` — нужен, чтобы прогресс кампаний и resume после рестарта были видны в `docker compose logs` |
| `MEMBERSHIP_CHECK_CONCURRENCY` | Сколько получателей проверять на членство в exclude-чатах одновременно во время dry-run | По умолчанию `5` |

Документация Telegram Bot API: https://core.telegram.org/bots/api

## Гарантии доставки (важно знать)

- Отправка двухфазная: получатель помечается `sending` перед вызовом API и
  `sent` сразу после успешного ответа. Если процесс упадёт между этими двумя
  точками, при рестарте такая запись считается **доставленной** (политика
  at-most-once: для рассылки дубль сообщения хуже одного пропуска). Такие
  записи видны в CSV-экспорте по пометке `resume: статус неоднозначен...` —
  максимум одна на бота за одно падение.
- Временные сбои (сеть, 5xx) повторяются до 3 раз, после чего получатель
  помечается `error` и виден в экспорте.
- Ошибка разметки (`can't parse entities`) останавливает всю кампанию
  (статус `paused`), никто не «сжигается» — исправьте текст и продолжите.
- Сервис должен работать строго в один процесс (никаких `uvicorn --workers`):
  на этом держится защита от двойного запуска кампании.

## Проверка работоспособности

`GET /health` — без авторизации, для деплой-скриптов/мониторинга: `{"status": "ok"}`
при 200, если процесс поднялся и своя база рассылок отвечает, иначе 503.

## Тесты

Прогнать все тесты:

```
source .venv/Scripts/activate
pytest tests/ -x -q
```

Тесты используют переменные окружения из `tests/conftest.py` (фиктивные токены,
временные SQLite-файлы) и не трогают реальные `.env`/базы ботов.
