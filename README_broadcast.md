# Деплой админки рассылок на VPS (64.23.190.210)

> По умолчанию сервис слушает только `127.0.0.1` (доступ через SSH-туннель) —
> это рекомендуемый безопасный режим. При желании порт можно открыть по IP
> сервера, переключив `BIND_ADDR` в `.env` (см. шаг 5, вариант Б, и предупреждение
> про HTTP без шифрования).

## 1. Бэкап всех баз данных

Перед любыми изменениями сделать бэкап баз ботов и (если уже существует)
базы рассылок:

```bash
ssh root@64.23.190.210
mkdir -p ~/backups/$(date +%Y-%m-%d)
cp /opt/bginfobot/data/bot_data.sqlite ~/backups/$(date +%Y-%m-%d)/
cp /opt/bginfoai/chat_logs.db          ~/backups/$(date +%Y-%m-%d)/
cp /opt/broadcast-admin/data/broadcast.db ~/backups/$(date +%Y-%m-%d)/ 2>/dev/null || true
```

## 2. Проверить, примонтирована ли `chat_logs.db` бота B на хост

```bash
docker inspect bginfoai --format '{{ json .Mounts }}' | jq
```

- На этом сервере уже примонтирован: `bginfoai/docker-compose.yml` содержит
  `./chat_logs.db:/app/chat_logs.db`, реальный файл — `/opt/bginfoai/chat_logs.db`.
  Используйте этот путь как `BOT_B_DB_HOST_PATH` (шаг 3). **Важно**: `chat_logs.db`
  лежит прямо в корне `/opt/bginfoai`, рядом с исходным кодом и `.env` бота B
  (там его Telegram-токен и, возможно, токены VK) — монтируем только этот файл,
  а не всю папку `/opt/bginfoai`, иначе секреты бота B станут видны внутри
  контейнера broadcast-admin.
- Если на другом окружении файл существует только внутри контейнера (нет
  хостового пути) — **сначала** добавьте volume в `docker-compose.yml` бота B,
  например:
  ```yaml
  volumes:
    - ./data/chat_logs.db:/app/chat_logs.db
  ```
  затем `docker compose up -d` для бота B, чтобы файл появился на хосте, и
  только после этого продолжайте деплой админки.
- Обе базы (`bot_data.sqlite` и `chat_logs.db`) на момент проверки не используют
  WAL-режим — рядом нет `-wal`/`-shm`/`-journal` файлов в состоянии покоя,
  поэтому точечный маунт одного файла для B безопасен и достаточен.

## 3. Скопировать проект и заполнить `.env`

Проект пока не выложен в git-репозиторий — переносить с локальной машины
через `scp`/`rsync`, аналогично соседям в `/opt` (`bginfobot`, `bginfoai`):

```bash
# с локальной машины (Windows, PowerShell/Git Bash):
scp -r d:/1PythonProjects/20260706SendUser/sendusers root@64.23.190.210:/opt/broadcast-admin

# на сервере:
ssh root@64.23.190.210
cd /opt/broadcast-admin
cp .env.example .env
nano .env
```

Если позже заведёте git-репозиторий — можно будет обновлять через
`git pull` вместо повторного `scp`.

Заполнить как минимум: `TELEGRAM_BOT_TOKEN_A`, `TELEGRAM_BOT_TOKEN_B`,
`ADMIN_PASSWORD`, `SECRET_KEY` (`openssl rand -hex 32`), `ADMIN_CHAT_ID`,
`BOT_A_DB_PATH`/`BOT_B_DB_PATH` (пути **внутри контейнера**, см. `docker-compose.yml`).

Также задать в `.env` хостовые пути к базам ботов (docker compose подхватывает
переменные из `.env` в той же папке) — маунты асимметричны:

```
BOT_A_DATA_DIR=/opt/bginfobot/data          # каталог — там только bot_data.sqlite
BOT_B_DB_HOST_PATH=/opt/bginfoai/chat_logs.db   # один файл — рядом код и .env бота B
```

И порт на хосте (внутри контейнера всегда 8080, см. `Dockerfile`) — на этом VPS
`8080` уже занят `medvopros-app`, `8081` — `vetvopros-app`, `5000` — `bginfoai`,
поэтому используем `8090`:

```
HOST_PORT=8090
```

Если и `8090` окажется занят — проверить командой `sudo ss -tlnp | grep ':<порт>'`
или `docker ps --format 'table {{.Names}}\t{{.Ports}}'` и выбрать другой свободный.

## 4. Запуск

Контейнер работает от непривилегированного пользователя (не root) — каталог
`./data` монтируется с хоста, и если он уже принадлежит `root` (обычная
ситуация, если раньше контейнер писал в него от root), приложению не хватит
прав создать `broadcast.db` и сохранять картинки кампаний. Перед первым
запуском после этого обновления (один раз):

```bash
sudo chown -R 1000:1000 /opt/broadcast-admin/data
```

```bash
docker compose up -d --build
docker compose logs -f broadcast-admin   # проверить, что стартовало без ошибок
curl -s http://127.0.0.1:${HOST_PORT:-8090}/health   # {"status": "ok"}
```

## 5. Доступ к админке

Режим доступа переключается переменной `BIND_ADDR` в `.env` (после её смены —
`docker compose up -d`, контейнер пересоздастся):

### Вариант А (по умолчанию, безопасно): SSH-туннель

`BIND_ADDR=127.0.0.1` — порт слушает только локально на сервере. С локальной
машины проброс:

```bash
ssh -L 8090:127.0.0.1:8090 root@64.23.190.210
```

Затем открыть в браузере: http://127.0.0.1:8090

### Вариант Б (просто, но менее безопасно): открытый порт по IP

`BIND_ADDR=0.0.0.0` — админка доступна напрямую: http://64.23.190.210:8090

⚠️ Трафик идёт по **HTTP без шифрования** — пароль и сессионная cookie передаются
открытым текстом, порт будут сканировать боты. Использовать только временно/на
свой риск. Для постоянной публикации лучше:
- ограничить доступ firewall'ом на свои IP:
  `ufw allow from <ВАШ_IP> to any port 8090`, либо
- поставить перед сервисом reverse-proxy с HTTPS (nginx/Caddy) и выставить
  `COOKIE_SECURE=1` в `.env`.

## 6. Порядок работы в интерфейсе

1. **Вход** — ввести пароль из `ADMIN_PASSWORD`.
2. **Дашборд** — проверить статистику по базам ботов A/B (сколько
   пользователей, сколько заблокировали бота) и список последних кампаний.
3. **Новая кампания** — указать название, текст сообщения, разметку
   (HTML/MarkdownV2/без разметки), выбрать одного или обоих ботов.
   Над полем текста есть панель форматирования (Ж/К/П/З, ссылка, код,
   спойлер): выделите фрагмент и нажмите кнопку — она обернёт его в
   соответствующий HTML-тег Telegram. Панель активна при разметке HTML.
   Можно приложить **картинку** (JPG/PNG/GIF/WebP, до 10 МБ): тогда
   сообщение уйдёт как фото, а текст станет подписью (лимит подписи —
   1024 символа против 4096 у обычного текста). Картинка грузится в
   Telegram один раз на бота и переиспользуется для всех получателей.
4. **Тест себе** — отправить текст кампании в свой чат (`ADMIN_CHAT_ID`)
   через выбранных ботов и убедиться, что форматирование корректно.
5. **Dry-run** — прогнать без реальной отправки: проверка членства в чатах,
   формирование финального списка получателей и счётчиков.
6. **Подтвердить отправку** — запускает реальную рассылку; страница кампании
   обновляется автоматически (раз в 2 секунды) и показывает прогресс по
   каждому боту (отправлено/пропущено/заблокировано/ошибка).
7. **Мониторинг** — следить за счётчиками на странице кампании до перехода
   в финальный статус (`done`/`failed`/`cancelled`).
8. **Экспорт CSV** — после завершения кампании выгрузить полный список
   получателей со статусами (кнопка «Экспорт CSV» на странице кампании).
